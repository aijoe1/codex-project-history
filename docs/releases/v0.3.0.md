# Codex Project History v0.3.0 — release candidate

This is a review packet for an **unreleased** local candidate. It is not a public release receipt.

## Changes

- Active and archived chat pickers start with the current VS Code project when a workspace is open.
- **Show all projects** and **Show current project only** switch scope without discarding typed search.
- Current-project search applies before the recent-chat limit, so older chats from the current
  repository or its worktrees are not crowded out by activity elsewhere.
- Opening a chat from another project in the current VS Code window requires confirmation.

## Validated on macOS

- 35 automated tests, syntax and shell checks, and VSIX packaging passed.
- A fresh isolated VS Code installation of this VSIX plus official Codex activated before and
  after **Developer: Reload Window**, without Project Chats activation or database errors.
- Owner screenshots showed two Acme chats in **Current project** after reload and, with search
  text preserved, two same-title Acme/storefront results in **All projects**. The owner previously
  observed the foreign-project warning in an installed isolated v0.3.0 window.
- A direct read of the official-runtime synthetic SQLite fixture returned two current-project
  chats and three total active chats. The installed and packaged runtime files match source.
- Candidate artifact: `dist/codex-project-history-0.3.0.vsix` (local, ignored by Git), SHA-256
  `43e45941a8431b59539ea033f12cb109ba6ebe652b3f62b2eb9246124cc25d79`.

## Limits and landing gate

- The fixture contains synthetic chats; it does not prove reopening a real chat. Normal VS Code
  and the dotfiles installation remain on v0.2.0.
- The Codex database schema and editor route are private compatibility surfaces. A future Codex
  update may require maintenance. Linux, Windows, and Marketplace distribution are unvalidated.
- This branch has not been pushed for review, merged, tagged, released, or synced to dotfiles.
  Those are separate landing and distribution decisions. Before a public release, review the
  exact branch diff, run CI on that commit, and approve the resulting release artifact.
